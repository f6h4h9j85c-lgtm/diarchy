# diarchy audit report

- Repository: diarchy (open source), github.com/f6h4h9j85c-lgtm/diarchy
- Round 1 audited: `b210468` on `main` (v0.1.0)
- Round 2 audited: `7ff9f89` on the integration branch, after the round-1 fixes
- Fixes landed on `main` at: `db05bfb (Release 0.2.0)`
- Date: 2026-10-25 to 2026-10-26
- Status: final. Every confirmed finding has a disposition: fixed with its branch and commits, or deferred with a reason.

## Method

Twelve audit lenses reviewed the repository at commit `b210468`: protocol-vs-code, engine-adversarial, store-crash-safety, mcp-contract, security, codex-plugin-facts, claude-plugin-facts, launcher-portability, docs-accuracy, test-quality, anti-slop-gaming and skills-and-prompts. Each lens reported findings with a file, line, claim, evidence, repro and proposed fix. The lenses produced 138 raw findings; exact dedup left 135 and semantic merge left 104 (F001 to F104). Every high or medium finding then went to three independent refuters, one per verification lens: reproduce (rerun the failure), spec (check the claim against the project's own docs and upstream documentation) and realism (judge whether the failure occurs in real use and what it costs). Every low finding went to one combined refuter. A finding survives with at most one refute of three votes, or zero refutes of one; its final severity is the median severity of the non-refuting votes (with two such votes, the lower one). Where a refuter corrected the claim, the corrected claim is the one reported below.

After every round-1 fix was integrated, a completeness critic named the areas round 1 had not covered and the new mechanisms the fixes introduced, and a second round audited them; see "Second round" below. Each confirmed finding, in either round, was fixed in its own git worktree and branch, and an independent reviewer approved each fix before it was merged; a fix the reviewer sent back was reworked and reviewed again.

### F001 [high] Marketplace install of the Claude plugin cannot start the MCP server: dist/ is gitignored and never built

`bin/diarchy.js:2` (proposed high)

**Claim.** After the documented marketplace install, the plugin cache copy has node_modules but no `dist/`: dist/ is gitignored, no tag or release contains it, and Claude Code's plugin install runs no build. `bin/diarchy.js mcp` exits 1 with ERR_MODULE_NOT_FOUND, `/mcp` never lists diarchy, and both hooks silently print nothing, contrary to INSTALL-CLAUDE.md, README.md and QUICKSTART.md.

**Evidence.** `bin/diarchy.js:2` imports `../dist/cli/index.js`, `.gitignore` lists `dist/`, and marketplace.json installs from source `./`. The official loading docs say the dependency install runs with `--ignore-scripts` in a separate folder, so `prepare` never builds. A real install with claude 2.1.310 reproduced the failure.

**Repro.**

```
S=$(mktemp -d); git -C <repo> archive HEAD | tar -x -C "$S"; node "$S/bin/diarchy.js" mcp --agent claude   # -> ERR_MODULE_NOT_FOUND .../dist/cli/index.js
```

**Fix.** Commit dist/ (or point the marketplace at a release ref containing it), or build into `${CLAUDE_PLUGIN_DATA}` from a SessionStart hook. Add a test that runs `bin/diarchy.js --version` on a `git archive HEAD` extract.

| Lens | Refuted | Severity | Reasoning |
|---|---|---|---|
| spec | no | high | No spec covers packaging; install docs and plugin docs contradict the tree. |
| reproduce | no | high | Real marketplace install: MCP server and both hooks dead. |
| realism | no | high | Matches the loading docs; Quickstart global install also fails. |

**Disposition.** Fixed by `fix/B1-1-F001` (b5e0e34); independent review approved.

### F005 [high] Launcher spawns `claude -p --permission-mode acceptEdits`, under which every diarchy MCP tool call and every non-read-only Bash command is auto-denied

`src/cli/launcher-config.ts:39` (proposed high)

**Claim.** With the default `claude -p --permission-mode acceptEdits` and no allow rule, hook or `--allowedTools` in the repo or the `init` config, the Claude PM's diarchy MCP calls (verified: `read`) and non-read-only Bash commands (verified: `git commit`) are auto-denied. The PM stalls at its first step; `diarchy start` cannot pass kickoff.

**Evidence.** A live run with the launcher's flags returned `permission_denials` for `mcp__plugin_diarchy_diarchy__read` and `Bash node -e`. The headless docs say commands outside the read-only set need `--allowedTools` or an allow rule; project allow rules are ignored in an untrusted folder.

**Repro.**

```
cd $(mktemp -d) && claude -p --plugin-dir <repo> --permission-mode acceptEdits --output-format json 'Call the diarchy read tool with {} and quote the result; then run: node -e "console.log(42)"' | jq .permission_denials   # both calls listed as denied
```

**Fix.** Add `--allowedTools "mcp__plugin_diarchy_diarchy__*" "Bash(git *)" "Bash(npm *)" "Bash(gh *)"` to the default args and the `init` config, and document it. A refuter verified zero denials.

**Disposition.** Fixed by `fix/B1-2-F005` (005f909); independent review approved.

### F007 [high] wait_for_reply ignores request cancellation; the orphaned loop advances the inbox cursor and the agent never sees the reply

`src/mcp/server.ts:254` (proposed high)

**Claim.** When a client cancels or times out `wait_for_reply`, server.ts:254-258 never passes `extra.signal` to the store, so the wait loop keeps running and its next `read()` persists the inbox cursor past the newly arrived message. The agent's next `read`, and the hooks that share the cursor, report zero unread messages although the message is in chat.md.

**Evidence.** The SDK drops the handler result after abort but does not stop the handler. A probe with an 800 ms client timeout showed `read` returning `"messages":[]` after a PROPOSE landed. Codex's default 60 s tool timeout cancels every 110 s wait.

**Repro.**

```
node <scratch>/mcp/probeC.mjs  (uses the SDK client with request option {timeout: 800} against `node bin/diarchy.js mcp --agent codex`)
```

**Fix.** Pass `extra.signal` into `waitForReply` and return without touching the cursor once aborted, or commit the cursor only when a result is returned. Reword INSTALL-CODEX.md:43-45 and add a cancellation test.

| Lens | Refuted | Severity | Reasoning |

**Disposition.** Fixed by `fix/B2-3-F007` (0646026); independent review approved.

### F009 [high] kickoff.md's line-based format is not round-trip safe: a goal line matching `- AC<n>:` bricks the goal and vault, and a multi-line AC is silently truncated so kickoff.md and budget.json disagree

`src/vault/store.ts:230` (proposed high)

**Claim.** kickoff.md's line format is not round-trip safe. (a) A goal-text line matching `- AC<n>: ` is accepted, after which every `loadKickoff()` caller (post, stop, reply, tick, render) throws `AC<n> is out of order`: nobody can post, stop or reply, and new kickoffs fail SINGLE_KICKOFF. (b) A criterion with a newline is stored whole in budget.json but parsed back truncated.

**Evidence.** `kickoffProblem` (store.ts:230-247) checks only word counts and lead; kickoff.ts:37 writes the goal text raw ahead of the AC lines. The injected kickoff exits 0; `stop` and `reply` then exit 1.

**Repro.**

```
P=$(mktemp -d); cd <repo>
node --import tsx src/cli/index.ts kickoff $'Real goal text\n- AC1: injected criterion' --ac 'the only real criterion' --slug inj --project $P
node --import tsx src/cli/index.ts stop --project $P   # AC1 is out of order, exit 1
```

**Fix.** In `kickoffProblem`, reject goal lines matching AC_LINE_PATTERN and CR/LF in goal or criteria, and let `stop` and `reply` fall back to budget.json.

| Lens | Refuted | Severity | Reasoning |
|---|---|---|---|
| reproduce | no | high | Confirmed on CLI and MCP; MCP says INTERNAL. |
| spec | no | high | Human control plane dead; no recovery. |
| realism | no | medium | Rare trigger, severe effect; medium. |

**Disposition.** Fixed. The first fix `fix/B2-4-F009` (65e1777) was sent back because U+2028 and U+2029 still bricked kickoff. The rework `fix/B2-4r-kickoff-unicode` (be7a88d) rejects every Unicode line terminator and passed review.
