## Post-fix audit (v0.3.0 changes)

Method. Once the V3 fix branches were merged, the code they changed was audited in six areas with one finder each: protocol, launcher, hooks, brief and docs at `16a8a9d` (every V3 branch except `fix/V3-7-smoke`), and the live-check tooling (diagnostics trail, `diarchy doctor`, `diarchy smoke` and their docs) at `21d6db0`, after `fix/V3-7-smoke` merged. Each finder audited only `git diff 30abe42..<head>` for its area, plus the code those changes call or are called by, and probed in archive copies with the fake driver and stub CLIs; no real model was called. Each high or medium finding went to two independent refuters, one reproducing it by running code and one judging realism and checking it against PROTOCOL.md, ANTI-SLOP.md and RENDERING.md. Each low finding went to one combined refuter. A finding survives only with zero refutes, and its final severity is the lowest severity any vote gave. Survivors reported by more than one area were merged and numbered PF1 to PF13 (areas audited at `16a8a9d`) and LC1 to LC5 (live check). Each was fixed in one of six batches based on `release-0.3.0`, in its own worktree and branch, and an independent reviewer approved each batch before merge.

### PF1 [medium] A parked lead is stranded when its duty is time-based or DONE (regression from 0.2.0)

`src/cli/start.ts:444` (area launcher, proposed medium; votes: reproduce medium, realism medium)

**Claim.** The 0.3.0 supervisor parked a PM that exited 0 when nextStep said it owed nothing, and woke it only when a message landed or another PM exited with none left running. nextStep reports nothing owed for two duties that no message brings: the lead waiting out the plan CHALLENGE window (it must DECIDE after two wait_for_reply timeouts, and the challenger's silence is legal) and the lead whose DONE preconditions all hold. A lead that ended its turn in either state while the challenger kept looping on wait_for_reply stayed parked until WALL_CLOCK (240 minutes by default). The same happened when the other agent was only waiting on another session's lease, contrary to PROTOCOL.md 8. v0.2.0 restarted such a lead with backoff, and its next turn decided or posted DONE.

**Fix.** `fix/V3R-1-park` (4612c48, merged at a6d359a); independent review approved. The lead is never parked in the plan CHALLENGE window (marked by a new NextStep.dueOnTimeout flag) or when a DONE draft passes the engine's own 9.2 check; those exits take the counted-restart path as in 0.2.0. A parked PM is relaunched once, using no restart, if no message lands within twice MAX_WAIT_MS (220 s). A PM waiting on another session's lease no longer counts as running, so the "no PM is left running" wake also fires when the last running PM starts waiting. PROTOCOL.md 8 and ARCHITECTURE.md state the shipped rule.

## Release

This round ships as version 0.3.0 in package.json and both plugin manifests. The release commit sets the version, and `v0.3.0` is tagged on that commit as part of this release; the CEO approved the additive protocol changes as a minor release. Stored files are compatible both ways: budget.json, chat files, kickoff.md, inbox and lease files keep the 0.2.0 format. F033 and F126 were fixed without a new budget.json field, and the stored-file schemas (`src/protocol/schema.ts`, `src/protocol/types.ts`) and the lock and lease code are unchanged since `30abe42`, so a 0.2.0 plugin copy or global CLI can share a vault during an upgrade. The 0.1.0 and 0.2.0 vault fixtures load and continue a goal under 0.3.0, the 0.2.0 one to DONE, and what 0.3.0 writes while continuing it parses under the 0.2.0 schema (test/protocol.test.ts "stored files written by v0.1.0" and "stored files written by v0.2.0"; test/vault.test.ts "a goal written by v0.1.0" and "a goal written by v0.2.0"). The 0.2.0 fixture, test/fixtures/vault/v0.2.0-goal, was written by the `30abe42` code itself through a committed generator that reproduces it byte for byte; it stops mid-EXECUTE with a review task that a 0.2.0 STATUS marked done, and test/fixtures/vault/v0.2.0-schema holds the compiled 0.2.0 schema the reverse check parses with (`fix/V3R-7-fixture`, d541f2f, merged at 7608477; independent review approved). busy_reviewing-stored-review-task-done.yaml pins the review-task fallback for goals stored by 0.2.0. The brain rollup is part of the same release. The first live two-model run is still to be done, on a machine with both CLIs installed and logged in, with `diarchy smoke` (CONTRIBUTING.md, "Live smoke test"). Until then the README status stays pre-alpha.
